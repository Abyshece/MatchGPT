# Browser tests

Playwright scripts that drive the real app in Chromium against a local
Supabase (`supabase/config.toml`), used to check every phase since Phase 8. Each prints what it
checked and exits non-zero on failure; screenshots go to `tests/e2e/.shots/`.

## Setup

```bash
npx supabase start && npx supabase db reset       # local backend from the migrations
VITE_SUPABASE_URL=http://127.0.0.1:54321 SUPABASE_SERVICE_ROLE_KEY=<from `npx supabase status`> npx tsx scripts/seed.ts
VITE_SUPABASE_URL=http://127.0.0.1:54321 VITE_SUPABASE_ANON_KEY=<from `npx supabase status`> VITE_MEMBERS_ON_WEB=true npm run dev
VITE_SUPABASE_URL=http://127.0.0.1:54321 VITE_SUPABASE_ANON_KEY=<from `npx supabase status`> VITE_MEMBERS_ON_WEB=false npx vite --port 3002
npm i --no-save playwright axe-core && npx playwright install chromium
```

Accounts you pass to the tests need the answers every member gives (`lib/profileRewards.ts`) and the
current Terms and Privacy Policy accepted, or the app asks for them before anything else:
`node tests/e2e/fill-required.mjs <email> [email…]` fills in what's missing, accepts the current
versions and recalls the rules (the 90-day reminder) for them. `fixtures.mjs` has the same as SQL
(`REQUIRED_DETAILS`, `CONSENTED`) and `agreeToTerms(page)` for the consent screen.

The tests drive the members' app in the browser on port 3000 (`VITE_MEMBERS_ON_WEB=true`), except
`website.mjs`, which checks the website as it is live (port 3002); `accessibility.mjs` and
`error-reports.mjs` use both.

Defaults match the local stack; override with `BASE_URL`, `WEBSITE_URL` (port 3002), `SUPABASE_URL`,
`SERVICE_ROLE_KEY`, `MAILPIT_URL`, `DB_CONTAINER` (the database container in
`docker ps`) and `CHROMIUM_PATH`.
